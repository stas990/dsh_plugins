# Рендерер диаграмм

Приватный плагин DeepSeek Harness. Не публикуется в npm и не предназначен для
передачи наружу: ставится локальной ссылкой в конкретный профиль.

Регистрирует один инструмент — `diagram_render`: агент описывает диаграмму
(узлы, связи, группы), плагин раскладывает её в фиксированном визуальном стиле
и сохраняет SVG и PNG в рабочую папку сессии.

Название и описание в Plugin Manager берутся из `locale/ru.json`, а тело
страницы плагина — из этого README (поле `meta.detail` не задано).

## Коротко о главном

- **Стиль не настраивается из спеки.** Палитра, шрифты, геометрия карточек,
  стрелки и раскладка заданы кодом — одинаковая спека всегда даёт одинаковую
  картинку.
- **PNG — в двойном масштабе (2×)**, для него нужен растеризатор
  `@resvg/resvg-js`. Если он недоступен, SVG всё равно записывается, а в
  результате появляется предупреждение.
- **Запись уважает песочницу сессии**: `read-only` — отказ, `workspace-write` —
  только внутри рабочей папки, `danger-full-access` — без ограничений.
- **Ошибки не исправляются молча.** Неизвестная иконка, лишний ключ, ссылка на
  несуществующий узел — отказ с сообщением и ближайшими вариантами.

## Установка и обновление

Плагин установлен в профиль `desktop` как `@local/dsh-diagram` — ссылкой
(`link:`) на эту папку.

- Через интерфейс: **Plugins → Add plugin**, указать эту папку.
- Через агента: `plugin_manager` с `action: install_bundle` и абсолютным путём
  к папке.
- Зависимость `@resvg/resvg-js` объявлена в `package.json`; локально уже
  установлена в `node_modules`.
- После правки кода модуль нужно перечитать: перезапуск DSH или выключение и
  включение записи `include:diagram-render` через `plugin_manager`
  (`set_plugin`). Второй способ применяется без перезапуска приложения.

## Использование

Достаточно попросить диаграмму в чате — агент сам соберёт спеку и вызовет
инструмент:

```
Нарисуй схему: Web client → API gateway → PostgreSQL, иконки browser/server/postgres.
```

Пример спеки:

```json
{
  "title": "Ingest pipeline",
  "direction": "LR",
  "nodes": [
    { "id": "api", "label": "API gateway", "kind": "service", "icon": "server", "accent": "blue",
      "note": "Accepts HTTPS and routes requests.",
      "notes": ["Validates tokens", "Rate limits clients"] },
    { "id": "queue", "label": "Event queue", "icon": "kafka", "accent": "amber",
      "notes": ["Buffers burst traffic", "Replays failed deliveries"] },
    { "id": "db", "label": "PostgreSQL", "icon": "postgres", "accent": "teal" }
  ],
  "edges": [
    { "from": "api", "to": "queue", "label": "publish" },
    { "from": "queue", "to": "db" }
  ],
  "groups": [
    { "label": "Backend", "nodes": ["api", "queue", "db"] }
  ]
}
```

| Поле | Значение |
|---|---|
| `title` | Необязательный заголовок над диаграммой. |
| `direction` | `"LR"` (по умолчанию) или `"TB"`. |
| `nodes[].id` | Короткий уникальный ключ, на него ссылаются связи и группы. |
| `nodes[].label` | Подпись узла, переносится на две строки. |
| `nodes[].kind` | Необязательная подпись помельче под названием, например `service`. |
| `nodes[].note` | Короткая ремарка внутри карточки; идёт первой. |
| `nodes[].notes` | До 6 пунктов списка после ремарки. Общий текст `note` + `notes` — до 320 символов. |
| `nodes[].icon` | Иконка из пака: id, `core/id` или алиас. |
| `nodes[].accent` | `blue`, `teal`, `amber`, `rose`, `violet`, `slate`. |
| `edges[]` | `from`, `to`, необязательные `label` и `dashed`. |
| `groups[]` | `label` и список `nodes` — рамка вокруг связанной группы. |

Параметры инструмента:

| Параметр | Значение |
|---|---|
| `spec` | Обязательный объект спеки. |
| `format` | `both` (по умолчанию), `svg` или `png`. |
| `output` | Базовый путь без расширения; по умолчанию `diagrams/<название из title>`, без заголовка — `diagrams/diagram`. |

### Заметки в узлах

Внутрь карточки можно положить короткое пояснение: `note` — один абзац, `notes`
— список до шести пунктов. Оба поля можно задать одновременно: плагин склеивает
их — сначала `note`, затем пункты — и только после этого проверяет общую длину
(320 символов). Если лимит превышен, хвост обрезается, а в результате приходит
предупреждение; приоритет у `note`, поэтому сначала расходуется его бюджет.

- Шапка карточки (иконка, название, `kind`) остаётся фиксированной — 68 px;
  ниже идёт тонкий разделитель и текст 11.5 px.
- Карточка растёт по высоте под текст. Узлы выравниваются по шапке, поэтому
  связи подходят на уровне названия, а не в середину заметки.
- После абзаца перед списком — небольшой отступ; список рисуется точками с
  висячим отступом: перенос строки продолжается под текстом, а не под маркером.
- Для читаемости лучше одно предложение и 1–3 коротких пункта: заметки
  увеличивают высоту узла и всего холста.

## Результат

```
diagrams/ingest-pipeline.svg    векторный оригинал
diagrams/ingest-pipeline.png    растр 2×
```

При совпадении имени добавляется суффикс `-2`, `-3`. В ответе инструмент
возвращает пути, размеры и предупреждения. Показать картинку в чате можно
обычной markdown-ссылкой на PNG.

## Стиль

Фиксирован для всех диаграмм: белый холст, чернила `#0F172A`, волосяные рамки
`#E2E8F0`, карточки шириной 236 px с шапкой 68 px (высота растёт от заметок),
слоистая раскладка слева направо или сверху вниз, ортогональные связи со
сплошными наконечниками, типографика system-ui (`Segoe UI`, `Inter`) с
поддержкой кириллицы. Иконка стоит в тонированном квадрате 40 px цветом
акцента узла.

### Алиасы

У каждой иконки есть алиасы (всего 232), чтобы спека оставалась смысловой:

```json
{ "id": "db", "label": "PostgreSQL", "icon": "postgres" }
```

Примеры: `postgres`, `db`, `sql`, `mongo`, `store` → `database`; `queue`,
`kafka`, `rabbitmq`, `sqs`, `event-bus` → `inbox`; `auth`, `token`, `jwt`,
`secret`, `api-key` → `key`; `cache`, `redis`, `memcached` → `zap`; `gateway`,
`proxy`, `ingress` → `router`; `browser`, `frontend`, `desktop` → `monitor`;
`docker`, `pod`, `k8s` → `container`; `payment`, `billing` → `credit-card`;
`security`, `waf` → `shield`; `worker`, `compute` → `cpu`; `s3`, `disk` →
`hard-drive`; `monitoring`, `metrics` → `gauge`.

Порядок поиска: точный id → `pack/id` → алиас (без учёта регистра) → другой
пак, если имя без префикса и совпадение однозначное. Неизвестное имя
отклоняется с ближайшими id и алиасами.

### Свой пак

Достаточно положить JSON в `icons/` — код менять не нужно:

```json
{
  "id": "acme",
  "title": "Acme cloud",
  "license": "internal",
  "icons": {
    "lambda": {
      "title": "Lambda",
      "aliases": ["function", "faas"],
      "elements": [["path", { "d": "M7 4v16M17 4v16M7 12h10" }]]
    }
  }
}
```

Сетка 24×24, `fill="none"`, `stroke-width="2"`, круглые окончания; `elements` —
формат Lucide (`[tag, attributes]`). Ссылка: `acme/lambda`, `lambda` (если имя
не занято другим паком) или любой алиас.

## Ограничения

- Только блок-схемы и архитектура: узлы, связи, группы. Sequence, timeline и
  матриц пока нет.
- Раскладка — детерминированная слоистая, не универсальный оптимизатор графа:
  плотные циклы и сетки дают длинные связи.
- До 80 узлов и 160 связей на диаграмму.
- Рамка группы рисуется, только если её область не содержит чужих узлов; иначе
  группа остаётся без рамки, а в результате приходит предупреждение с именами
  «лишних» узлов.
- У узла без иконки `accent` ни на что не влияет.
- Подписи не переводятся и не сокращаются по смыслу: длинные обрезаются с
  предупреждением.
- Заметки увеличивают высоту карточки: 320 символов текста — это примерно
  12 строк, карточка высотой около 280 px, и холст растёт вместе с ней.

## Структура

| Файл | Назначение |
|---|---|
| `index.js` | Точка входа: регистрирует инструмент на `ctx.tools`. |
| `lib/tool.js` | Определение инструмента, запись файлов, проверка песочницы. |
| `lib/spec.js` | Валидация и нормализация спеки. |
| `lib/render.js` | Раскладка, маршрутизация связей, сборка SVG, стиль. |
| `lib/png.js` | Загрузка растеризатора и экспорт PNG. |
| `lib/icons.js` | Загрузка паков, разрешение id и алиасов. |
| `icons/core.json` | Пак `core` с иконками и алиасами. |
| `locale/en.json`, `locale/ru.json` | Название и описание для Plugin Manager. |
| `icon.svg` | Иконка плагина 36×36. |

Служебные скрипты разработки лежат вне пакета, в корневом `../tools`:
`make-icons.mjs` пересобирает `icons/core.json` из `icon-nodes.json`
(Lucide 0.468.0), `test-*.mjs` — проверки спеки, алиасов и песочницы,
`render-*.mjs` — эталонные рендеры. В `files` пакета они не входят.
